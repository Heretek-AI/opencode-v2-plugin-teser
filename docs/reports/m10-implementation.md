# M10 Implementation Report — Results, report, CLI run/validate/init/report

- **Stage ID:** M10 (report: `src/report/` + `src/run.ts`, utils, CLI, `src/index.ts`, examples, unit/e2e tests)
- **Date:** 2026-10-17
- **Branch:** `impl/v1` (not committed, per task instructions)

## Summary

Implemented the M10 runner surface: a central `CaseResult`/`ResultsFile`
shape, a pure Markdown renderer with required/allowed-failure/skip cells
and per-failure `<details>` blocks, the `run` orchestrator (load → tier 1 →
tier 2 → skipped-live → bun-test → results.json + report.md → exit code),
a hand-parsed CLI (`init`, `validate`, `run`, `report`, `--version`,
`--help`), the public programmatic API, and the `init` example templates.
Acceptance verified manually and by automation: `run` in `tool-basic`
passes and writes `report.md`, `run` in `throws` exits 1, `validate` in
`no-entry` exits 2, and a unit test snapshot-checks the Markdown.

## Files created

- `src/report/results.ts` — `CaseResult` (exact M10 shape: `id`,
  `tier: "load"|"scripted"|"live"`, `opencode`, `pass`, `skipped?`,
  `description?`, `failures?`, `tools?`, `steps?`, `costUSD?`,
  `tokens?`, `durationMs`, `textExcerpt?`, `attempts?`, `judge?`,
  `kept?`) and `ResultsFile { version: 1, at, tool, plugin, results }`.
- `src/report/markdown.ts` — `renderMarkdown(results, opts?
  { allowedVersions?, sha? })`, `gitSha()` (`GITHUB_SHA` else
  `git rev-parse --short HEAD` else `"unknown"`), `appendStepSummary()`
  (appends to `$GITHUB_STEP_SUMMARY` when set, never throws). Header with
  plugin/tool/opencode versions/SHA/totals; one `Tier|Case|Result|Tools|
  Steps|Cost|Time` table per opencode version; cells `✅ pass`, `❌ fail`,
  `⚠️ allowed failure`, `⏭️ skipped (reason)`; `<details>` per failure
  with the failure list and `kept` evidence path; live cost/token totals.
- `src/util/log.ts` — `createLogger({quiet, verbose})`; info suppressed
  when quiet, debug only when verbose, warn/error always (error even when
  quiet).
- `src/util/rows.ts` — `rows<T>(json)`: normalizes `[]` or `{data: []}`.
- `src/util/fs.ts` — `ensureDir`, `isFile` (never throws), `writeJsonl`,
  `readJsonl` (missing file → `[]`, bad lines skipped), `appendFile`
  (never throws).
- `src/run.ts` — `runCi(opts?)` orchestrator plus `isTuiOnly()` and the
  `TierName`/`RunOptions`/`RunOutcome` types. Order per spec: load+validate
  → resolve entries (exit 2 upstream) → install/build once → per version:
  resolve binary, tier 1 (`runLoad` or `runUiStatic`), tier-1-failure marks
  tier 2/3 `skipped: "tier 1 failed"`, TUI-only marks tier 2/3
  `skipped: "TUI-only plugin"`, tier 2 via `pool(concurrencyLimit())`,
  live scenarios `skipped: "live tier not implemented (M11)"` → bun-test
  escape hatch (once, `OPENCODE_BIN` = required binary, last-40-lines
  failures) → `results.json` + `report.md` + step summary. `--gate` warns
  (M12) and continues. `--keep` sets `OPENCODE_PLUGIN_CI_KEEP=1` (chose env
  over churning M8/M9 tier signatures). Exit: 0 unless a required-version
  case failed (`!pass && !skipped`).
- `src/index.ts` — programmatic API: `Sandbox`, `startStub`,
  `readProbe`, `evaluate`, `check`, `resolveEntries`, `writeShim`,
  `resolveOpencode`, `parseEvents`, `textOf`, `toolUses`,
  `probePluginDirs()`, plus related types, `renderMarkdown`,
  `appendStepSummary`, `runCi`.
- `examples/.opencode-ci/config.yaml` + `scenarios/example.yaml` —
  minimal valid init templates (M13 will expand).
- `test/unit/report.test.ts` — fixed-`ResultsFile` assertions (header,
  tables, all four result cells, `<details>` + evidence, live totals)
  plus `toMatchSnapshot()`.
- `test/e2e/cli.test.ts` — spawns the real CLI with `Bun.spawn` (async)

## Self-audit notes

- Fail-closed: schema/entry errors → `ConfigError` → exit 2; unexpected
  runtime errors in `run` → exit 1; bad results files in `report` →
  exit 2 with usage. Skips never pass a failing gate: exit counts only
  `!pass && !skipped` on the required version.
- No stubs: `live` is an explicit skip with reason (M11 owns it); gate is
  an accepted-but-warn flag (M12 owns it). Both are reported, not hidden.
- Async spawn only for opencode and `bun test` (`Bun.spawn`); sync spawn
  used solely for `git rev-parse` in `gitSha()` (no event loop at stake).
- Two off-by-one `import.meta.url` bugs caught by manual testing:
  `src/run.ts` and `src/cli.ts` used `../../package.json` /
  `../../examples/...` (one level too many); fixed to `../…`.
- A `**/` sequence inside a `/** … */` comment in `src/run.ts` closed
  the comment early and broke typecheck; reworded. Grep confirms no
  other `/**/`-style `*/` sequences in block comments (one remaining
  `**/` is in a `//` comment, safe).
- Not committed, per task instructions (`git status` shows M10 files
  staged as modified/untracked, ready for review).
